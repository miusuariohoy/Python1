2 Tuplas: listas que no se cambian

Una tupla es igual a una lista pero congelada: se define con paréntesis y después no se puede modificar. Analogía: la lista es una carpeta donde podés agregar hojas; la tupla es un libro impreso.

lambda: una función escrita en una línea

Paso 0 · cómo trabaja command. En un botón, command=saludar va SIN paréntesis: no llamamos a la función ahora, le entregamos a Tkinter su dirección para que la llame recién con el click. 

def doble(x):                # función normal
    return x * 2

lambda x: x * 2              # EXACTAMENTE lo mismo, en una línea
PedazoSignificadoEquivalente en def
lambda"acá empieza una mini-función sin nombre"def nombre():
xlo que recibeel x de los paréntesis
: x * 2lo único que hace y devuelvereturn x * 2

El problema: nuestros botones necesitan mandar el número de tabla. Pero esto… 

Button(frame2, text="7", command=mostrar_tabla(7))  # MAL: los paréntesis ejecutan YA

…ejecuta la función al crear el botón, no al hacer click. Y sin paréntesis (command=mostrar_tabla) falta el número y da error en el click. Hace falta algo intermedio: lambda. 

boton7 = Button(frame2, text="7", command=lambda: mostrar_tabla(7))
  1. Python crea la mini-función lambda: mostrar_tabla(7) y la guarda en command. Todavía NO se ejecuta nada.
  2. Hacés click en el "7".
  3. Tkinter llama a esa mini-función (por eso funciona sin paréntesis: la invoca vacía).
  4. La mini-función corre su única línea: mostrar_tabla(7). Recién AHORA se dibuja la tabla del 7.
FormaQué pasa
command=mostrar_tablafalta el número n: error al hacer click
command=mostrar_tabla(7)se ejecuta YA al crear el botón (mal)
command=lambda: mostrar_tabla(7)espera el click Y manda el 7 (correcto)
Idea clave: lambda no ejecuta nada por sí sola: fabrica la función y la deja lista, como un papelito que dice "cuando te llamen, mostrá la tabla del 7". Tkinter guarda el papelito y lo lee en cada click.
Límite: lambda admite UNA sola expresión (una línea). Si necesitás varias instrucciones o un if complejo, usá def normal.

5 Canvas: dibujar, poner imagen y animar

El Canvas es un lienzo donde se colocan formas e imágenes, y cada objeto queda identificado por un id para poder moverlo después. Es el escenario del sapo de LasTablas.py.

Sintaxis canvas = Canvas(ventana, width=1500, height=90)
sapo = canvas.create_image(100, 55, image=img_Tk)
canvas.coords(sapo, x, y)  # mover
Crear lienzo e imagen
from PIL import Image, ImageTk

canvas = Canvas(frame5, width=1500, height=90)
canvas.pack()

img = Image.open("Sapo.jfif").resize((100,100))
img_Tk = ImageTk.PhotoImage(img)

sapo = canvas.create_image(100, 55, image=img_Tk)

create_image(x, y, image=...) devuelve el id del objeto (acá, sapo). Ese id es el que se usa después para moverlo.

Moverlo en cada vuelta
# Mueve la imagen a la nueva posición
canvas.coords(sapo, x, ALTO // 2)

coords(id, x, y) teletransporta el objeto a esa posición. Cambiar las coordenadas muchas veces seguidas = animación.

La animación completa: rebote izquierda-derecha
x, direccion = 100, 1            # direccion 1=derecha, -1=izquierda

def mover():
    global x, direccion
    x += 10 * direccion           # avanza 10 px por vuelta
    if x <= 100 or x > 1300 - 100:
        direccion *= -1           # tocó un borde: invierte el sentido
    canvas.coords(sapo, x, ALTO // 2)
    base.after(30, mover)          # re-agenda: ~33 cuadros por segundo

mover()                            # primera llamada: arranca el loop
  • x += 10 * direccion: suma si dirección vale 1, resta si vale -1.
  • El if de bordes multiplica la dirección por -1: rebota.
  • after(30, mover) re-agenda: el mismo patrón del cronómetro de la Parte 1.
  • global es obligatorio para modificar x y direccion dentro de la función.
Error clásico con imágenes: guardar img_Tk solo dentro de una función hace que la imagen desaparezca (el recolector la borra). Guardala en una variable global.
Buena práctica: nombrá el id con algo que se entienda (sapo, pelota), así coords(sapo, ...) se lee solo.

Una función chiquita que devuelve la conexión abierta. Las demás funciones la llaman cada vez que necesitan hablar con MySQL: abren la puerta, usan la base y la cierran.

try / except: la red de seguridad

Hay operaciones que pueden fallar aunque el código esté bien escrito: MySQL apagado, un archivo que no existe o el usuario escribió letras donde iba un número. Sin protección, ese error cierra el programa. try / except es el plan B: intenta lo riesgoso y, si falla, ejecuta otra cosa en vez de explotar.

Sintaxis try:
    lo_que_puede_fallar()
except:
    qué_hacer_si_falla()
Ejemplo mínimo: convertir lo que escribe el usuario
try:
    edad = int(input("Tu edad: "))   # zona protegida
    print("Tenés", edad, "años")
except:
    print("Eso no es un número")      # plan B: el programa sigue
ParteQué haceEn este proyecto
try:intenta las líneas protegidas (con sangría)conectar() + INSERT
except:se ejecuta SOLO si algo fallóshowerror("No se pudo conectar")
sin tryel error corta el programala ventana se cierra de golpe
Cómo leerlo: “intentá esto; si no se puede, hacé aquello”. El except no es el error: es la respuesta que dejamos preparada. En guardar() y mostrar() vas a ver este mismo patrón.
Ojo con la sangría: todo lo que puede fallar va dentro del try. Si queda afuera, el error no se atrapa y el programa se cierra igual.
PASO 3 · ENVIAR: def guardar()
def guardar():
    nombre = entrada_nombre.get()
    curso = combo_curso.get()

    if nombre == "" or curso == "":
        messagebox.showwarning("Falta dato", "Completá todos los campos")
        return

    try:
        cnx = conectar()
        cursor = cnx.cursor()
        sql = "INSERT INTO alumnos (nombre, curso) VALUES (%s, %s)"
        cursor.execute(sql, (nombre, curso))     # los valores viajan en una TUPLA
        cnx.commit()                             # confirma el cambio
        cnx.close()
        messagebox.showinfo("Guardado", "Alumno agregado con éxito")
    except:
        messagebox.showerror("Error", "No se pudo conectar a la base")
  1. .get(): saca de la ventana lo que escribió/eligió el usuario.
  2. Validación ANTES de tocar la base; return corta la función si falta un dato.
  3. try: si MySQL está apagado no rompe el programa, salta al except y avisa con showerror.
  4. Pide la conexión a conectar() y crea el cursor: el "lápiz" que escribe sobre la base.
  5. Los %s son huecos; los valores viajan en una tupla aparte (nunca concatenar strings del usuario al SQL).
  6. commit() confirma el cambio; sin esa línea, el INSERT se pierde.
  7. close() cierra la puerta y showinfo celebra.
PASO 4 · MOSTRAR lo guardado (SELECT)

Mismo camino que ENVIAR, con distinto final: INSERT cambia datos y necesita commit(); SELECT solo consulta y responde con fetchall(). 

def mostrar():
    try:
        cnx = conectar()
        cursor = cnx.cursor()
        cursor.execute("SELECT nombre, curso FROM alumnos")
        filas = cursor.fetchall()            # devuelve LISTA DE TUPLAS
        # ej: filas = [("Ana", "1A"), ("Bruno", "2A")]

        texto_alumnos.delete("1.0", END)      # limpia antes de escribir
        for fila in filas:                    # cada fila es una tupla
            texto_alumnos.insert(END, f"{fila[0]} - {fila[1]}\n")

        if len(filas) == 0:
            messagebox.showinfo("Sin datos", "Todavía no hay alumnos")
        cnx.close()
    except:
        messagebox.showerror("Error", "No se pudo leer la base")
HerramientaQué hace
cursor.execute(sql)envía el SELECT (sin tupla de valores: no hay datos que proteger)
cursor.fetchall()trae TODAS las filas juntas, como lista de tuplas
fila[0] / fila[1]campo por posición: el orden es el MISMO que se pidió en el SELECT
Los cinco pasos, de un vistazo
PasoLíneaSi falta…
1. abrir conexiónconnect(host, user, password, database)todo lo demás falla
2. crear cursorcnx.cursor()no hay quién ejecute SQL
3. ejecutarcursor.execute(sql, tupla_valores)nada llega a la base
4. confirmarcnx.commit()el INSERT se pierde al cerrar
5. cerrarcnx.close()conexiones colgadas
Error clásico Nº1: olvidar commit(). El programa dice que guardó, pero al abrir phpMyAdmin no hay nada: la operación quedó pendiente.
Buena práctica: validar ANTES de tocar la base (campos vacíos con showwarning) y proteger la conexión con try/except para responder con showerror si MySQL está apagado.
